## Meaning of the failure

At this pinned transport revision, `cache_miss` denotes an HTTP 404 returned
for the exact authenticated package request. It establishes that the artifact
was unavailable to the observed salts-core workflow token. It does **not**
distinguish an unpublished version from a package/version hidden from that
token. The same jobs successfully restored other exact dependencies; that
does not establish permission to every individual package.

Source: [pinned HTTP handling](https://github.com/qigao/vcpkg-cache/blob/7bb5b556a001bc82d2922a04a718e986a7f47f54/scripts/github-packages.py).
GitHub documents separate package Actions access for the NuGet registry:
[NuGet authentication](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-nuget-registry)
and [package permissions](https://docs.github.com/en/packages/learn-github-packages/about-permissions-for-github-packages).
